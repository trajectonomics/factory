# QA runbook

How the product is tested the way a customer meets it. Five **Surfaces** are tested as published, by simulated customers: `docs`, `site`, `cli`, `skills`, `core` ([ADR 0020](./adr/0020-five-surface-briefs-replace-the-generic-finder.md)). A daily pass tests one Surface. The launch check tests all five before a release and ends in one verdict the owner reads ([ADR 0019](./adr/0019-qa-findings-enter-dispatch-at-their-severity.md)).

Language is in [`GLOSSARY.md`](../GLOSSARY.md). The rules here are the only ones: a skill is a pointer, and a scheduled task reads this file from `origin/main` on every run.

**The published truth.** A pass tests what a customer gets, never `main`. `git show origin/main` reads the Factory's rules; it says nothing about the product.

```bash
npm view @trajectonomics/cli dist-tags --json          # what `latest` resolves to
gh api repos/trajectonomics/cli/releases/latest --jq '.tag_name, .published_at'
curl -s -o /dev/null -w '%{http_code}\n' https://trajectonomics.com/docs/
curl -s https://registry.npmjs.org/@trajectonomics%2fmoney | jq -r '.readme | length'
```

Record every pin in the report: the package versions, the release tag, the live URLs, the skill source and commit. A capability that exists on `main` and not in `latest` is not a capability. When a published Surface promises it, that is a **major** finding against the Surface that promises it, named `release truth`.

## Severity

| Severity | Means | Example |
| --- | --- | --- |
| **blocker** | A first-time customer cannot get from install to a correct result; money or tax is wrong; a secret is exposed; a published page 404s or contradicts the release | `traj init` fails; `balance` prints a wrong total; the install command on the homepage is not the install command |
| **major** | A documented or promised path fails, or a promise has no destination; a workaround exists | The homepage promises planning that the release does not do; a README names a command `latest` rejects |
| **minor** | Friction a customer gets past: wording, a missing example of output, a page that needs one more sentence | A command page shows the invocation but never the result |
| **noise** | The pass itself: a flake, a broken persona script, an environment problem | A persona ran out of context; the network dropped |

Noise is never an issue. It is one line in the report and nothing else.

## Filing

Every `blocker`, `major` and `minor` finding is an issue in the repository that owns the Surface: `docs`, `site`, `cli`, `skills`, or the core package's repository (`money`, `ledger-core`, `tax-core`, `sim-core`).

1. **Fingerprint first.** Compute `fingerprint: <surface>/<check>/<normalized failure>`, lowercase, punctuation dropped, digits kept (`cli/first-run/init-downloads-105mb-silently`). Search open **and** closed issues for it (`gh search issues --repo trajectonomics/<repo> '"fingerprint: <value>"'`). A match means **comment on that issue** with the new run, pins and reproduction, and file nothing. Only a finding with no match opens an issue. A closed match is reopened by a comment, never by a new issue.
2. **Labels.** `qa` plus exactly one of `qa-blocker`, `qa-major`, `qa-minor`. Create a missing label in the repository before using it: `qa` `BFD4F2`, `qa-blocker` `B60205`, `qa-major` `D93F0B`, `qa-minor` `FEF2C0`.
3. **The drafting lane.** `qa-blocker` and `qa-major` also get `needs-triage` in the same `gh issue create` call, so a Spec drafter takes them. `qa-minor` gets neither: it waits for the owner's word, and an agent adds `needs-triage` when the owner says `go`.
4. **Never** add `ready-for-agent`, `ready-for-human` or `wontfix`, never close an issue, and never edit an existing issue body.
5. The body starts with `> *This was generated by AI during QA.*`, carries the fingerprint, and follows [the finding issue](#the-finding-issue).

**The ledger is GitHub.** Every finding carries its fingerprint, so open and closed `qa-*` issues are the append-only record; nothing else is needed and no file is updated per pass. A file ledger was considered and dropped: writing one needs a pull request a day, and a pull request of one JSON line then needs two reviews (dispatcher runbook, step 9).

### The finding issue

```markdown
> *This was generated by AI during QA.*
<!-- factory:qa v1 -->
fingerprint: <surface>/<check>/<slug>
run: <yyyymmdd> <surface> (<model>)
pins: <package@version, release tag, live URL, skill commit>

## What a customer sees
<One paragraph. Which persona, what they were trying to do.>

## Reproduce
<The exact commands, in order, with the directory or URL. Paste the output, not a summary.>

## Expected
<What the page, the help text or the docs promised, quoted, with its link.>

## Severity
`blocker` | `major` | `minor` — <one line why, against the table in the QA runbook.>

## Fix shape
<Optional. One line. Never a plan: the Spec drafter writes the plan.>
```

## Personas

A **Persona** is a fixed description of a customer an agent plays. The roster is one file per Persona under [`personas/`](./personas/README.md), versioned like code, and the index there carries the rotation.

- A Persona may use only what a stranger has: the live site, the live docs, npm, the GitHub README, the published skill. It never reads the repository, a runbook, an ADR or a source file, and never opens a local checkout of the Surface it tests. This is the rule that separates evidence from theatre.
- A Persona run pastes every command and every output, in order. A claim without a paste is not evidence and is dropped from the report.
- A Persona ends with three lines: where it stopped, what it misunderstood, and what it would tell a friend.
- The panel is 3–5 Personas per pass, rotated by the index; the launch check runs all of them.

## One daily pass

The scheduled thread is a launcher, like the Dispatcher: it checks the guards, places one QA thread, reports, and stops.

1. **Guards.** Launch nothing and report if any holds: the kill switch file `/home/prame_assistant/.factory-stop` exists; the Surface's repository has an open issue carrying `factory:pause`; or the quota probe (`timeout 15 pi -p --no-session --no-tools "Reply with OK only."`) shows `pi` has no quota, in which case report `no-quota` and skip the day. A top-level QA thread runs DeepSeek only and has no fallback model.
2. **Launch one thread** with `t3_thread_launch`, in the `factory` project on a ready host (dispatcher runbook, step 7), choosing the host with fewer live `qa/` threads:
   - `title`: `qa/trajectonomics/<surface>`; `clientRequestId`: `qa-<surface>-<yyyymmdd>`;
   - `runtimeMode`: `full-access`;
   - `modelSelection`: primary provider `pi`, instance `pi`, model `command-code/deepseek/deepseek-v4.1-flash`;
   - `workspaceStrategy`: `worktree` from `origin/main` on branch `qa/<yyyymmdd>-<surface>`.
   The message is the launch message below. A launch that fails with `branch_already_exists` retries once with `-r2`, as dispatcher runbook step 8 says.
3. **Report** in under 6 lines: guards, the Surface, the host, the thread link. Do not wait for the thread.

Launch message (fill in and send):

> You are the Factory QA thread for the `<surface>` Surface on `<yyyymmdd>`. Read the QA runbook, `docs/qa-runbook.md`, with `gh api repos/trajectonomics/factory/contents/docs/qa-runbook.md -H "Accept: application/vnd.github.raw"` and follow it from "One daily pass" step 1 to the final line for that Surface only. It is your whole instruction; read it in full before you act.

## The QA thread

0. Read this runbook, [`GLOSSARY.md`](../GLOSSARY.md), the Surface's own `AGENTS.md` and `README` from `origin/main`, and the Persona files for the panel.
1. Pin the published truth with the commands above, and write the pins down before testing anything.
2. Run the Surface playbook below. Every check prints what it ran.
3. Run the panel. Personas run as `delegate_task` children in one message, `mode: "wait"`, on the same DeepSeek model, each with its Persona file and the playbook's task. They are read-only and told to file nothing.
4. Turn findings into issues under [Filing](#filing): fingerprint, dedupe, labels, `needs-triage` only on `blocker` and `major`.
5. Leave nothing behind: no push, no branch of a Surface repository, no edit to any Surface repository. A scratch directory made with `mktemp -d` is deleted before the report.
6. Finish with one line: `QA <surface>, pins <versions>, checks <passed>/<total>, findings <n> (<b> blocker, <m> major, <i> minor), issues <urls or none>, panel <n>, noise <n>`.
7. Settle the thread (`t3_thread_organize`, `action: settle`) when the report leaves nothing for the owner: no finding the pass could not file and no question in the thread. Findings are issues now; the thread is done. Leave it unsettled when a finding waits on a decision in the thread.

## The five playbooks

Each playbook names its reader, its target and its checks. A target is met or it is a finding; it is never a score to watch.

### `docs`

Reader: a customer, and the agent working for them. Target: an agent-docs score of 85 or more, and 90% of the question set answered from the docs alone.

- `npx -y afdocs check https://trajectonomics.com/docs/` — record the score and each sub-score. Content Discoverability and Markdown Availability must be 100.
- `curl -s -o /dev/null -w '%{http_code}' https://trajectonomics.com/docs/llms.txt` and one page twin (`/docs/cli/commands/tx.md`) and `curl -sI -H 'Accept: text/markdown' <page>`.
- **Release truth against the docs.** Read the command list the release prints (`npx -y @trajectonomics/cli@latest schema --json | jq -r '.commands | keys[]'`) and the pages under `/docs/cli/commands/`. Every released command and flag has a page; no page documents a command the release rejects.
- **The question set.** Every question in [`qa-questions.md`](./qa-questions.md), drawn from answered issues, `--help` output and error strings. Answer each closed-book: docs pages only, no web, no source, no `--help`. Grade by literal string (a flag, an exit code, a JSON field, a page URL). Pass is 90% with the right page cited and no invented flag.
- Personas: `vibe-coder-agent`, `thai-employee`.

### `site`

Reader: a developer deciding in ten seconds. Target: a stranger can say what the product is and run the command, and every promise has a destination.

- `/`, `/th/`, `/en/` return 200 or the documented redirect; `lang` is correct; a 404 in each language is a real page.
- Every `href` on both language homes returns under 400.
- `<title>` and the `h1` name what the product is, as a noun phrase. A rotating slogan with no noun phrase is a **major** finding for the copy.
- **Every promise has a destination.** Each capability claim is quoted, then checked against `npm view @trajectonomics/cli dist-tags` and against a docs page that teaches it. A claim the release cannot back, or that no docs page covers, is a **major** finding on the Surface that promises it.
- The install command on the page is run verbatim in a `mktemp -d` scratch directory, and its stated prerequisites are enough to make it work.
- Copy rate is read from the owner's dashboard when it exists; when it does not, the check reports `not instrumented` and files nothing.
- Personas: `thai-marketer`, `skeptical-senior-dev`.

### `cli`

Reader: a stranger with a real ledger, at a terminal, alone. Target: install to a correct first result, once, with nothing guessed.

- `npx -y @trajectonomics/cli@latest --version`, `--help`, `schema --json` — record the command count.
- The first-run flow in `mktemp -d`, with `TRAJ_HOME` inside it, timed: `init`, four `account add`, two `tx add`, `balance --as-of`, `report networth`, `report pnl --until`. Record the wall time to first correct result.
- Exit codes and error text: a group command with no subcommand, an unknown flag, an unsupported currency, a missing value. Wrong exit code, a hint that names no flag, or a validator sentence shown to a customer is a finding.
- Every command and flag in the README of the release exists in the binary; no README command prints `unknown_command`.
- `TRAJ_HOME` contains no surprise: a first `init` says what it downloads, how large, and where.
- Personas: `beginner-mac`, `ci-automator`, `accountant-reconciler`.

### `skills`

Reader: an agent mid-task, installed by a customer. Target: pass^3 on a 20-task suite, and no invented command.

- Install in `mktemp -d`: `npx -y skills@1.7.6 add trajectonomics/skills --skill traj-onboarding -y`, then confirm what was installed and from where (`skills list --json`). An unpinned or unverifiable download is a finding.
- The skill's claims against the release: every command it names is in `schema --json`, every file or flag it names exists. One command outside that list is a **blocker**.
- Every task in [`qa-tasks.md`](./qa-tasks.md), run 3 times; all three must pass (pass^3), and a task that passes 2 of 3 is a finding, not a pass.
- 20 labelled queries (10 should trigger the skill, 10 should not, including near-misses), 3 runs each; record the trigger rate. A skill that fires on a neighbouring task is worse than one that never fires.
- The version check: the skill states the version it expects, or it does not, and the report says which.
- Personas: `skill-installer`, `vibe-coder-agent`.

### `core`

Reader: a developer on the npm page, then in an editor. Target: the page is not blank, and the first example runs.

- `@trajectonomics/money`, `ledger`, `tax`, `sim`: `curl -s https://registry.npmjs.org/@trajectonomics%2f<name> | jq -r '.readme | length'` is not 0, `jq -r .version`, and the tarball's file list.
- The README's first example, copied verbatim into a `mktemp -d` project with the published version installed, produces the output the README shows. A blank npm page, a missing Install line, or an example that does not run is a finding: `blocker` when the page is blank, `major` otherwise.
- Every exported symbol a README names exists in the published types (`jq` over the `.d.ts`, or `tsc --noEmit` on the example).
- A version policy is stated (semver promise, changelog). Absent, it is a `minor`.
- Personas: `package-integrator`, `security-reviewer`.

## The launch check

The owner runs it before a release; `factory-launch-check` is the skill that points here. It tests all five Surfaces at one pinned version, runs the whole roster, and files nothing.

1. Pin the release that is about to ship: the tag, the npm versions, the deploy commit of `docs` and `site`, the skill commit. If the thing under test is `main` and not a release, say so and refuse a `SHIP` verdict.
2. Run all five playbooks and the full roster.
3. Take the verdict to a second view: `delegate_task` once, `role: "review"`, `mode: "wait"`, `target: { providerInstanceId: "antigravity", model: "gemini-4-hydrogen", options: { thinking_level: "medium" } }`, giving it the pins, the blocker list and the findings, and asking whether anything marked non-blocking is a blocker and anything marked blocker is not. If that provider has no quota, say so in the report and keep the verdict it could not confirm.
4. Write [the launch report](#the-launch-report) as the last thing you write. File no issue and open no pull request.

**A blocker is** a first-time customer who cannot get from install to a correct result, wrong money or tax, an exposed secret, or a published page that 404s or contradicts the release. Nothing else blocks. A large list of `minor` findings does not block a launch and is never presented as if it did.

### The launch report

```markdown
# Launch check, <date>

## Verdict
`SHIP` | `SHIP-WITH-WAIVERS` | `NO-SHIP` — <one line.>

## Tested
<tag, npm versions, docs deploy commit, site deploy commit, skill commit, and the second view: model, agree or disagree.>

## Blockers
<One line each: Surface, what a customer cannot do, the reproduce line. "none" when none.>

## Scorecard
| Surface | Verdict | Checks | Time to first result |
| docs | PASS/WARN/FAIL | <passed>/<total> | — |

## Everything else, worst first
<Findings by Severity, one line each.>

## Not tested
<Each check skipped and why, so `SHIP` is never read as complete coverage.>

## Waivers
<Only for `SHIP-WITH-WAIVERS`: what is knowingly shipped and who accepted it.>
```

## Guards and limits

- A pass never edits a Surface repository, never pushes a branch, and never changes a host or a cloud platform.
- One pass tests one Surface. A pass that finds work in another Surface names it in one line and leaves it to that Surface's pass.
- An upstream release that changes the published truth (a new `latest`, a new deploy) invalidates the pins in every report before it; the next pass re-pins.
- The kill switch, the per-repository `factory:pause` and the `pi` quota are the only brakes. There is no cap on findings ([ADR 0019](./adr/0019-qa-findings-enter-dispatch-at-their-severity.md)).
